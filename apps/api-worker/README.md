# TideGrid API Worker

Hono on Cloudflare Workers. Routes live under `/v1`; every request and response schema comes from `@tidegrid/contracts`, and the OpenAPI document is generated from the routes (`pnpm contracts:generate` at the root).

Local development: copy `.dev.vars.example` to `.dev.vars` with the runtime role's connection string, then `pnpm dev`. The Worker prefers a `HYPERDRIVE` binding when one is configured and falls back to the `DATABASE_URL` secret. Deploy only when the owner asks, with `pnpm run release`; the build id in `/v1/health` comes from `git describe --always --dirty`.

Payments (G2.7): the `dev` environment sets `PAYMENT_PROVIDER=fake`, the demo's payment shim; give it a `FAKE_PAYMENT_WEBHOOK_SECRET` of at least 32 characters in `.dev.vars`. Without one, or anywhere `PAYMENT_PROVIDER` is unset, checkout answers 503 `payments_unavailable`. A production configuration refuses the fake outright. `scripts/shim-replay.ts` drives a running Worker through the fake provider and the real webhook route and records the state before and after each delivery, replay, and reordering; its header says how to run it against a throwaway branch. The contracts are in [domain-booking](../../packages/domain-booking/README.md) and [domain-payments](../../packages/domain-payments/README.md).

Email and guest self-service (lane 1, G2.11c and the G2.16 shim): the `dev` environment sets `EMAIL_PROVIDER=fake`, the demo's email shim, and `GUEST_LINK_ORIGIN` (`http://{slug}.book.localhost:5173`; set it in `.dev.vars` for another guest port). Without `EMAIL_PROVIDER`, email is off: messages are still written with their changes, and none is sent. `EMAIL_FROM_ADDRESS` names the sender (default `bookings@tidegrid.us`). A production configuration refuses the fake. Email goes out right after the request that wrote it commits (in `waitUntil`, on its own one-connection pool), and the cron's third job sends the rest, retries, and finishes attempts whose lease lapsed. The local mailbox is at `/v1/fake-email/mailbox`, only when `EMAIL_PROVIDER=fake` and `ENVIRONMENT=local`; elsewhere it answers 404. The guest routes (`/v1/public/booking-access`, `/v1/public/manage/...`) and the staff reads of a booking's participants and messages are listed in the [booking contract](../../packages/domain-booking/README.md#api); the lifecycle hooks are built once in `src/booking-hooks.ts`. `scripts/email-shim-evidence.ts` drives a running Worker (`wrangler dev --test-scheduled`) through the send after commit, replayed payment events, repeated sweeps, a retry, a refusal, and a lost provider answer, and ends with a control total of deliveries per message; its header says how to run it. The contracts are in [domain-messaging](../../packages/domain-messaging/README.md).

Hostnames, CORS, and the guest Worker's gateway (G2.14b):

- **One resolver.** Every public route reads the tenant from the browser Origin through the strict origin parser in [domain-hostnames](../../packages/domain-hostnames/README.md) (`src/public-tenant.ts`): `https` only, no port, no path, no trailing dot, lowercase ASCII, and `http`, ports, and `*.localhost` names only when `ENVIRONMENT=local`. Anything else, an unknown, pending, disabled, or suspended host included, answers the same 404 `tenant_not_found`. Host, `X-Forwarded-Host`, and Referer are never read. The bootstrap (`/v1/public/tenant`) and the guest Worker's gateway share `loadPublicExperience`; `/v1/public/trips` resolves before it validates its query.
- **CORS** (`src/hostnames/cors.ts`). Every route keeps `ALLOWED_ORIGINS`. Only when `PUBLIC_CORS=dynamic` (set in `env.dev` and `env.test`; unset or anything else is the static allowlist, the deployed default and the rollback), `/v1/public/*` and `/v1/fake-provider/*` also echo a canonical origin whose host resolves to an active, verified hostname, and `/v1/public/tenant` echoes any strictly parsed origin, so the guest page can read "not published" from its 404. Preflights and simple requests answer CORS from an in-isolate projection (30 seconds, 1,000 origins); a lookup it cannot answer goes through a per-address limit, and a simple request's lookup is the route's own. The route always resolves the tenant afresh. Credentials are never allowed, and `Vary: Origin` is on every answer.
- **`GuestGateway`** (`src/index.ts`, `src/hostnames/guest-gateway.ts`). A service-binding entrypoint for the guest Worker with one method, `resolveHost(host)`: it checks the host itself, then answers `found` with public brand fields only, `miss`, or `withheld`, and throws on a database failure. It has no `fetch`, never carries the console mark, and so reaches no staff or sign-in route. Each call opens and closes one database connection, with no rate limit; that is acceptable for the demo and listed for G2.14b-live in the demo build plan.
- **Custom hostnames** (`src/hostnames.ts`). Off unless `HOSTNAME_PROVIDER` names a provider. `fake` is accepted only when `ENVIRONMENT=local` and no `CF_SAAS_ZONE_ID` is set (stricter than the payment and email fakes, because the deployed API runs `ENVIRONMENT=preview`); the sweep reads it only when a test hands it one, since a fake built in a Worker knows no hostname. `cloudflare_saas` needs `CF_SAAS_ZONE_ID` (a var) and the `CF_SAAS_API_TOKEN` secret. The cron's fourth job, the hostname sweep, records provider readings and demotes what is no longer servable. Requesting, activating, and disabling are the admin CLI's, in [tools/hostnames](../../tools/hostnames/README.md).
